# PhysiBoard 2.0 — the overhaul

**Status:** planned, not started. Nothing ships until all of Phases 1–3 are done and signed off.
**Last updated:** 2026-08-27
**Baseline:** `main` @ v1.2.4 (`b36f036`)

The fork stops being a Pastiera derivative in everything but license: upstream's name leaves the
tree, the multi-device generality goes, preferences migrate, and users land on known-good T2E
defaults. Ships as **2.0.0**.

---

## 1. Decisions (settled — do not relitigate)

| # | Decision | Rationale |
|---|---|---|
| D1 | **Name stays PhysiBoard.** | Tagline already says "keyboard and toolbox for the Titan 2 Elite". A name carries two of {identity, category, device}; the third belongs in the tagline. Recognition on r/unihertz is worth more than a rename. |
| D2 | **`Pastierina` and `PhysiBar` both die.** Naming becomes PhysiBoard (product) / T2E Tools (hub) / Status Bar (the strip). | One concept had two names, and *Pastierina* is upstream's brand sitting inside our pref keys. Killing `FULL_STATUS_BAR` removes the need to name a mode that has no alternative. |
| D3 | **T2E is the supported device. `titan2` is kept but explicitly untested.** Other seven profiles deleted. | No T2 hardware to test on. Keeping the profile costs one asset dir; claiming support we can't verify costs trust. |
| D4 | **Keep all 10 locales; English is the source of truth; the English override stays discoverable.** | International product. `app_language_tag` already exists — verify it isn't buried. |
| D5 | **Phase 2 deletes only what's dead-by-consequence. Bloat waits for Phase 4.** | Mixing mechanical and product deletion makes regressions ambiguous. Phase 2 must be verifiable. |
| D6 | **The forced re-enable becomes onboarding.** Everyone lands on T2E defaults with their content layered on top. | Fixes the root cause of both 2026-08-27 bug reports (see §2). We pay the re-onboarding cost regardless; take the fix for free. |
| D7 | **Migration preserves content, resets behaviour.** Plus an auto-exported pre-migration backup and a "Restore my old settings" button. | Shitty behavioural settings shouldn't survive; user-authored work must. The backup makes being opinionated safe. |
| D8 | **Test builds are side-by-side (`.test`) until the migration rehearsal.** | Never install a debug build on the phone — the signature change forces an uninstall and loses prefs *and* the broker pairing. |
| D9 | **Work on branch `v2-t2e`. `main` stays at v1.2.4 and releasable.** Git history kept. | Escape hatch for an urgent 1.x patch mid-refactor. History is our provenance record. |
| D10 | **Version 2.0.0.** No new features in scope; requests evaluated as they arrive. | v2 is subtraction and reorganisation. |

## 2. Why this is worth doing (the evidence)

Both bug reports on 2026-08-27 had **one root cause**: `applyImpactDefaultsIfNeeded` is called only
from `MainActivity`. Anyone who enabled the keyboard from Android's own settings and never opened
the app has been running **upstream Pastiera defaults** the whole time.

- A user saw an accent row the maintainer had never seen — they never received
  `status_bar_variations_visible=false`, and upstream's default was `true`.
- A Titan 2 user lost suggestions entirely at 1.2.2 — they never received `show_status_bar`, and
  1.2.2 flipped the upstream fallback from `true` to `false`, collapsing the whole strip.

The generality *is* the bug source. D6 makes this class of failure structurally impossible.

## 3. Fixed points

Only two things cannot move. Both are external identity, not code.

| Fixed | Why | Consequence of changing it |
|---|---|---|
| `applicationId = brobata.physiboard` | `/data/data/<applicationId>/` is keyed by it | Different app: no update path, installs side-by-side, **cannot read the old data dir → migration impossible** |
| Signing key, cert SHA-256 `89a050fcb37aa14a16d77c737c70caaebdc4c7f10156f9dc8933adb3499c3261` | Update path | Uninstall-first, wipes everything. Backup: `~/shared/physiboard-signing/` |

**Everything else renames freely**, including the IME service class, the tile service, the
Application class, the Java namespace, and the prefs filename. State is carried by migration;
Android-owned identity records are re-established by the user re-onboarding (D6).

Target namespace: `it.palsoftware.pastiera` → **`brobata.physiboard`** (matches applicationId; no
second spelling).

## 6. Phase 3 — Migration, then rename

**Highest risk. Ordering is deliberate: the migration ships and is proven before the rename depends on it.**

### 6.1 The migration

`PastieraApplication` → `PhysiBoardApplication`. No component declares `android:process`, so the IME
and UI share one process and one hook covers both.

```kotlin
class PhysiBoardApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        SettingsMigration.migrateIfNeeded(this)   // MUST be first — line below already reads prefs
        SettingsManager.initializeAltShiftLayoutSwitchDefault(this)
        ...
```

Order of operations inside `migrateIfNeeded`:

1. If `physiboard_prefs` already has `prefs_migrated_v2`, return.
2. **Export a full backup of `pastiera_prefs` first** (`BackupContract`), to `filesDir`. This is the
   undo for D7.
3. Copy every key from `pastiera_prefs` → `physiboard_prefs`, dispatching on type. **`Set<String>`
   must be handled** — `status_bar_apps` and `additional_ime_subtypes` are string sets and a naive
   `when` drops them silently.
4. Apply the rename table (§6.2), then the drop table (§6.3).
5. Reset behavioural keys to T2E defaults; leave content keys as migrated (§6.4).
6. `putBoolean("prefs_migrated_v2", true)`, **`commit()` not `apply()`** — the IME can read prefs
   microseconds later and `apply()` would race.
7. **Do not delete `pastiera_prefs`.** Leave it one release as a rollback net; delete in 2.1.

Copy-then-transform (not allowlist) so keys added later aren't silently lost.

### 6.2 Key renames (value carried)

| From | To |
|---|---|
| `pastierina_status_bar_slots_left` | `status_bar_slots_left` |
| `pastierina_status_bar_slots_right` | `status_bar_slots_right` |
| — derive — | `status_bar_slot_left`, `status_bar_slot_right_1/2` kept in step |

This is the fix for "the Extended slot config becomes dead". The surviving bar reads the
*Pastierina* slots today; the dying row reads `status_bar_slots_*`. Mapping Pastierina → the clean
name means **users keep their real button layout** under a name that isn't upstream's.

### 6.3 Key drops (concept gone)

```
pastierina_mode_active, pastierina_mode_override          (one mode now)
status_bar_variations_visible                             (second row gone)
static_variation_bar_mode / _preset / _base_layer_enabled
static_variation_bar_modifier_hold_restoration
dynamic_variation_bar_slot_count / _resize_to_content
clicks_*                                                  (~20 keys, fleet gone)
```

Normalise any physical-profile override naming a deleted profile → `titan2elite_qwerty`.

### 6.4 Content vs behaviour (D7)

**Always migrate — user-authored, never "shitty":**
`launcher_shortcuts`, `launcher_shortcuts_enabled`, `app_enter_behavior_overrides`,
`status_bar_apps`, `sym_pages_config`, `additional_ime_subtypes`, user dictionary, custom
autocorrect substitutions, text expansions.

**Reset to defaults** — the remaining ~220 behavioural keys.

**Free:** everything in `filesDir` (`variations.json` etc.) — `/data/data/brobata.physiboard/files/`
is untouched by either rename.

**`impact_defaults_applied`:** do **not** migrate. D6 requires everyone to land on current defaults.

### 6.4b Backup filename

Exports were named `pastiera-backup-<stamp>.zip`; now `physiboard-backup-`. Safe: `RestoreManager`
matches on entries *inside* the archive (`prefs/pastiera_prefs.json`), never the archive name, so
existing backups still restore.

### 6.5 Backup compatibility

`BackupContract.prefName = "pastiera_prefs"`. Users hold exported backups carrying that name —
**restore must accept both names** and apply §6.2/§6.3 on the way in, or every existing backup
becomes unrestorable.

### 6.5b Kill the Pastiera release-notes fallback

`update/ReleaseNotesFetcher.kt` carries a hardcoded de/it/en fallback blob titled **"Pastiera
$version"** describing *upstream's* features. Any PhysiBoard user whose GitHub fetch fails sees
Pastiera's name and release notes. Delete the block; the app reads `whats_new.md` since 1.2.1.

### 6.6 The rename

One mechanical commit. 394 files currently mention `pastiera`/`palsoftware`.

- namespace + all packages → `brobata.physiboard`
- `PhysicalKeyboardInputMethodService` → new package (forces re-enable — expected, D6)
- `KeyboardBacklightTileService` → new package (user re-adds the tile)
- prefs file → `physiboard_prefs`
- attribution consolidated into `NOTICE.md`; `LICENSE` untouched; `PHYSIBOARD_CHANGES.md` continues
  as the GPLv3 §5(a) record
- `upstream` remote removed; drop the `pastiera` GitHub topic
- **CI gate:** zero `palsoftware`/`pastiera` identifiers outside `LICENSE`, `NOTICE.md`,
  `PHYSIBOARD_CHANGES.md`, and `res/values-it/`

**Licensing note:** verified — **no source file carries a copyright header**, so nothing is being
stripped. GPLv3 requires keeping `LICENSE`, stating modification (§5(a)), and not claiming sole
authorship. It does not require keeping upstream's name in packages, classes, paths, or UI.

### 6.7 Onboarding (D6)

Re-enabling *is* onboarding. Detect "not the enabled IME" → explain what happened → deep-link
`Settings.ACTION_INPUT_METHOD_SETTINGS` → `showInputMethodPicker()`. Reuses `OnboardingScreen`.
Include **"Restore my old settings"** wired to the §6.1 step-2 backup.

Move defaults out of `MainActivity` so the never-opened-the-app class of user cannot exist again.

## 7. Phase 4 — IA rebuild

### 7.0 Maintainer's walkthrough, 2026-08-28 (first pass — re-run this when Phase 4 starts)

**Delete outright**
- Smart Features (under Advanced) — the whole section
- The duplicate *Feedback* section — Sound and Haptics already covers it
- The whole *Modifiers* section — LEDs belong to the status bar and should be on by default, not chosen
- *Open Fn layer* settings — already in key bindings
- Voice: the Alt+Ctrl voice shortcut
- Enter key behaviour: the advanced "bind something else to Enter" section — key bindings' job

**Move**
- Screen trackpad → T2E Tools
- Hold-key-for-assistant selections → key bindings
- All assistant settings → their own *Voice Assistant* section

**Reword**
- Voice's *Feedback* header reads wrong for vibrate/sound

**Findings from investigating the maintainer's questions**
- *Respect manual shift off* does **not** affect capitals at box-start or after a period. It means:
  when you deliberately press Shift to cancel an auto-capital, don't re-apply it for the rest of that
  field session. Off = auto-cap overrides your explicit Shift. Recommend deleting the toggle and
  keeping the behaviour on.
- *Experimental suggestions* switches between nothing — there is one engine. It is a second master
  off-switch for suggestions, ANDed with the real one, and off means no suggestions at all on a
  physical keyboard: the same failure the Titan 2 user reported. Delete it, treat as always on.
- *Show LEDs* (keyboard themes) is not disabled, it is **software-keyboard only**
  (`StatusBarController` picks `softwareThemeSettings.showLeds` only when in full software mode;
  hardware uses the modifier-indicators setting). Toggling it does nothing on the hardware keyboard,
  and the UI never says so.

**Still open**
- Extras — not walked through yet
- Whether the *moves* are genuine moves (binding surface must accept them) or deletions on the
  understanding key bindings already covers it


40 settings screens. Design work, scoped separately after a menu-by-menu screenshot pass.

Known smells:
- Four navigation containers: `Settings`, `SettingsHub`, `CustomizationSettings`, `AdvancedSettings`
- Three autocorrect screens: `AutoCorrectSettings`, `AutoCorrectionCategory`, `AutoCorrectEdit`
- Dev tools shipped to users: `ImeTest`, `KeyboardLayoutViewer`

**Pre-approved deletion candidates:** anything already hidden. The codebase hides rather than
deletes — *"Status bar 'style' picker hidden to simplify"*, *"Swipe-cursor info row hidden to
declutter"*, *"rounded-corner insets option hidden"*. Already judged not worth showing. Collect the
full hidden list before the screenshot pass so it only covers what's still visible.

Candidate feature (only if it earns its place): fingerprint-health readout from `dumpsys biometric`
via the broker — measurement where the platform allows no control. See
[[double-tap-to-wake-not-possible]]: no sensitivity or timeout setting exists at any level.

## 9. Pre-flight verifications (before anything reaches the phone)

1. ~~**Re-capture the impact defaults from the real phone.**~~ ✅ DONE — captured 2026-08-27 from app 1.2.3 via the app's own backup export. Confirmed the drift: `applyImpactDefaultsIfNeeded` is a
   snapshot of the maintainer's config taken in `e7ae00d` (v1.0.4). `status_bar_visibility` did not
   exist until `09b3b59` (v1.2.2), so the block still writes the legacy `show_status_bar=false` —
   the live phone has `show_status_bar=true` **and** `status_bar_visibility=APPS`, so the shipped
   default directly contradicted the maintainer's own config. Also drifted: `dictation_end_silence_ms`
   (2500 shipped vs 2000 live). Missing entirely: `status_bar_height_dp`, `screen_trackpad_step_px`,
   `side_key_assistant`, `auto_replace_on_space_enter`, `notification_ring_*`. Shipped default for
   visibility is **ALWAYS**, not the maintainer's APPS — flag for review.
2. ~~**Fallback IME exists.**~~ ✅ PASSED 2026-08-27. `com.iqqijni.bbkeyboard` (stock) is installed
   **and already enabled** alongside PhysiBoard; Gboard is installed too. The rename cannot leave
   this phone unable to type. **This check also found a real hazard:** BB Keyboard was offered as
   `Tier.OPTIONAL` bloat, so the toolbox could remove the fallback it depends on. Now in `DENYLIST`
   (`80f0b1f`).
3. ~~**Broker pairing survives.**~~ ✅ ANSWERED — the pairing lives in its **own** SharedPreferences
   file, `embedded_adb`, not in `pastiera_prefs`. Renaming `pastiera_prefs` does not touch it, and
   the data dir is unchanged, so the pairing survives with no migration work at all.
4. **Pinned launcher shortcuts.** Dynamic shortcuts republish on start and self-heal; *pinned* ones
   store the component and will break. Confirm the blast radius.
5. **Migration rehearsal.** ✅ RUN 2026-08-28 against the sideload build, not the daily driver:
   installed the pre-rename build, ran it, upgraded to 2.0 in place. Results: no crash; the IME's
   old component disappears and Android falls back to the stock BB Keyboard exactly as pre-flight
   #2 predicted; the new component registers. **Found a real bug** - seed-once guards were being
   reset, letting one-time setup run over carried content (`70624c1`).

   Not yet confirmed on device: the migration's own log line never reached `logcat` (the string is
   in the APK; this ROM does not surface app logs for a non-debuggable build), and the migration
   notice was never seen because the rehearsal install had `tutorial_completed=false`. The carry
   itself is covered by 12 unit tests. **Remaining check: complete the tutorial in a pre-rename
   sideload, upgrade, and confirm the notice appears with the undo button.**

## 10. Pre-mortem

1. **A phone that can't type.** Rename lands, PhysiBoard is the only IME, no fallback. → §9.1,
   plus the release *before* 2.0 warns in What's New that a re-enable is coming.
2. **Settings vanish.** Migration bug, or `apply()` racing the IME. → `commit()`, `pastiera_prefs`
   kept one release, pre-migration backup, restore button, rehearsal on real hardware.
3. **The rename half-lands** and the tree carries two brands forever — worse than either end state.
   → one commit, CI grep gate (§6.6).

## 11. Working agreement

- Branch `v2-t2e`; `main` stays at v1.2.4 and releasable (D9).
- Each drop/phase ends with: `.test` APK on the phone → written diff summary → **maintainer
  actually tests it** → then commit. No phase starts before the previous is signed off.
- Nothing merges to `main`, nothing is tagged, nothing is published until Phases 1–3 are done and
  the migration rehearsal has passed.
- 1.2.4 stays live as Latest in the meantime.
